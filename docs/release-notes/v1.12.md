## IgnisDisc v1.12

Free, open-source (GPL-3.0-or-later) CD/DVD burner, audio CD ripper and multi-disc archiver for Windows 10 and 11 (x64).

### Downloads and SHA-256 checksums
- **Installer** (`IgnisDisc-Setup.exe`, 81.9 MB, per-user, no admin rights): `E078984B52E6DFFBBADCCBB07AC1771D3D3063210A9D2EFF344E1174B4E0B683`
- **Portable** (`IgnisDisc-Portable-win-x64.zip`, 81.3 MB): `D1904A1EAA6C8AC5DA184D6B1B81FFD6A66035F9798D6D59E11CE37591D71BF2`

Builds are not code-signed yet, so Windows SmartScreen may warn on first run.

### Direct drive commands (experimental, off by default)
IgnisDisc can now burn CDs with its own drive commands instead of Windows' burning service. It is switched on per burn ("Direct drive commands (experimental)" on the Audio CD, Data Disc and Disc Image screens, `--native` on the command line); the Windows writer stays the default.
- **Audio CDs** (`burn-audio --native`): Session-at-Once with CD-Text in the lead-in, ISRC and catalog (UPC/EAN) codes, pre-emphasis and copy flags, the `INDEX 00` gap marks of a `.cue` sheet, and audio in front of track 1. After writing, the whole disc is read back: track list, CD-Text, codes and every audio sample are compared, and the burn only counts as a success if they match.
- **Data CDs** (`burn-iso --native`, `burn-data --native`): one data track written Track-at-Once at a speed picked from the drive's own list, then read back sector by sector. DVDs, Blu-ray discs and discs that already hold a session are still burned by the Windows writer, and the result says so.
- **Test writes** with the laser off (`--test-write`), and a log of every drive command for each direct burn.
- Run on real hardware on one drive so far (LG GP60NB50): audio on a CD-RW and a CD-R with every feature above, data on a CD-RW. Treat other drives as untested.

### Checking a burn
- **The check after a burn reads the disc, not the drive's memory.** A drive can answer a read from what it still holds from the burn. The check now forces the drive to read the disc itself where that can happen (the last part written and the start of the disc) and reads the rest normally. **Strict verify** (Settings, or `--strict-verify`) forces every read; it is several times slower.
- **Damage is reported by file**: bad or unreadable sectors are listed with the files they belong to.
- **Optional hash lists on the disc**: `--sha256sums` / `--blake3sums` (and checkboxes on the Data Disc screen) add `SHA256SUMS` / `BLAKE3SUMS` to the disc root, and the check after a burn compares every file against them.
- The Image screen's verify and the `verify` command read from the disc in the same way.

### Disc images
- **UDF 1.50, 2.00, 2.01, 2.50 and 2.60** can be written as well as 1.02 (`--udf-rev`; 1.02 stays the default), with a separate reserve copy of the volume descriptors.
- **Reproducible images**: `--fixed-time` (or `SOURCE_DATE_EPOCH`) makes the same folder build to the same bytes.

### Archive discs
- **Recovery data fills the disc**: PAR2 recovery data now uses the space left on each archive disc; the redundancy percentage is a minimum (`--no-fill` keeps it exact).
- **New `recover` command**: reads a damaged archive disc or image with retries, copies the files out, rebuilds damaged ones with par2 and checks them against both checksum lists.

### Drives and media
- **Write speeds from the drive**: the speed picker offers the speeds the drive itself reports for the inserted disc when Windows gives none; `media-info` shows them, and the formatted capacity of rewritable discs.
- **Blu-ray, BDXL and M-DISC media are recognised** (type, size, layers), and the Data Disc screen shows how the data splits across layers on dual-layer and multi-layer discs. Burning Blu-ray is untested (see below).

### Fixed
- Rips and copies of a rewritable DVD (DVD+RW) were one sector short, losing the disc format's closing anchor record.
- File names longer than 64 characters were shortened without notice on discs left open for more sessions and on added sessions. The burn result now says how many names were shortened.
- Straight after a session was added, a drive could go on reporting the disc's old layout; the app no longer takes that at its word, and tells you to reinsert the disc if Windows still shows only the earlier files.
- Archive verification missed files that were listed in only one of an archive disc's two lists, and passed an empty or unreadable list.
- `VERIFY.PS1` on archive discs failed when started from PowerShell 7.
- PAR2 repair could fail when some recovery files were missing although enough data remained; a failed repair no longer leaves renamed originals behind.
- CD-Text with missing or duplicated packs was accepted when read.

### Other
- The licence is now GPL-3.0-or-later, with a trademark policy (`TRADEMARKS.md`) and the licence notice shown in the app and the command-line tool.

### Known limitations
- Direct drive commands are experimental: CD only, and tried on one drive model. DVD and Blu-ray always use the Windows writer.
- On a drive that keeps showing a simulated session after a test write, a real burn needs the disc reloaded first; `--test-first` stops after the test and says so.
- DVD testing for this release covered DVD+RW and DVD-R on one drive. DVD-RW, DVD+R and dual-layer discs were not tried.
- No disc from this release has been played in a stand-alone CD or DVD player.
- Blu-ray discs are recognised, but burning one has never been tried on a real drive.
- Discs left open for more sessions hold file names of up to 64 characters.
- Burn results report the speed that was asked for, not the speed measured.
- Disc copy has been tested against the built-in virtual drive; please report results from real drives.
