## IgnisDisc v1.14

Free, open-source (GPL-3.0-or-later) CD/DVD burner, audio CD ripper and multi-disc archiver for Windows 10 and 11 (x64).

### Downloads and SHA-256 checksums
- **Installer** (`IgnisDisc-Setup.exe`, per-user, no admin rights): checksum is added here once the files are built.
- **Portable** (`IgnisDisc-Portable-win-x64.zip`): checksum is added here once the files are built.

Builds are not code-signed yet, so Windows SmartScreen may warn on first run.

### Rip to MP3, Opus and AAC
- Audio CDs can now be ripped to **MP3, Opus or AAC (.m4a)** as well as WAV and FLAC (the rip screen's format list and bitrate box; `rip-audio --format mp3|opus|aac --bitrate <kbps>`). Files are tagged with title, artist, album and track number.
- AAC uses the encoder built into Windows. MP3 and Opus use the optional ffmpeg download; no encoder is bundled. A missing encoder or a bitrate the format does not accept is reported before the disc is read.
- A rip that still has sectors reading wrong after re-reads now says so on its first line, in the JSON (`complete: false`) and with exit code 2.

### Direct drive commands: more discs, more checks (experimental, off by default)
The direct writer is still opt-in ("Direct drive commands (experimental)" in the app, `--native` on the command line); the Windows writer stays the default. Every direct burn is read back and compared afterwards.
- **Sessions added to a disc left open**: a CD-R, CD-RW, DVD-R, DVD-RW or DVD+R left open now gets its next session from the direct writer, with the earlier files kept. On real discs (LG GP60NB50): three sessions each on a CD-RW, a CD-R and a DVD+R and four on a DVD-R, every file of every session read back identical. DVD-RW has run only in the simulator.
- **DVD+R** written and finalized on a real disc (single and multi-session). **Dual-layer DVD+R** (with the layer break set before writing) and **dual-layer DVD-R** (layer jump recording, on drives that offer it), **DVD-RAM** (formatted first when new) and single-layer **BD-R and BD-RE** are new too, but have run only in the built-in drive simulator.
- **Mixed-mode CDs** (a data track, then audio) from a `.cue` sheet, and whole-disc copies of them. Tried on a real CD-RW and CD-R: the copy matched the original, CD-Text included.
- **DVD-Video** can be burned with the direct writer (`burn-dvd --native`, or the DVD-Video screen); one test disc on a real DVD+RW read back and decoded in full. On a dual-layer DVD+R the layer break goes on a cell boundary, where players expect it (simulator only).
- **Archive discs** can be burned with the direct writer too (Archive screen switch, `archive-burn`).
- **Write offset**: direct audio burns now correct the drive's write offset, using AccurateRip's drive list (downloaded when needed, never bundled). On a real CD-R a secure rip then matched the source files sample for sample.
- **Test write then real write in one go** on drives whose tray closes by itself (not yet tried on such a drive); spring trays still need the disc reloaded by hand.
- The read-back check after an audio burn now tells a hard-to-read CD (a weak disc read back as the drive guessed) apart from one written wrong, by re-reading the doubtful sectors carefully.

### New commands and screens
- **copy-disc**: copy a disc from the command line, with one drive (it waits for the blank disc) or two, several copies. A copy stops before writing if source audio still reads wrong; the app now asks instead.
- **check-disc** and a **Check disc** button in Drive Utilities: reads a CD once with error pointers, as a player would, and says whether it reads cleanly, is weak in places or is damaged, and where.
- **verify --cue**: checks an audio or mixed-mode CD against its cue sheet without writing (track table, CD-Text, codes, every sample).
- **rip --raw** of a mixed-mode CD now covers the whole disc and writes a cue that burns back as the same disc.
- **Archive sets** pack largest files first (fewer discs) and every disc carries a catalog of the whole set (`CATALOG.JSON` and a searchable `INDEX.HTML`).
- The Audio CD screen has **ISRC and catalog number fields** that point out typos, and keeps a cue sheet's flags, gap marks and hidden audio.

### Safer defaults
- **Write speed**: the default now comes from the drive's own speed list for the inserted disc, preferring constant-speed (CLV) settings up to 16x on CD and 8x on DVD. A CD-R batch known to read weakly after burning (FORNET) gets a lower default in the app, with the reason shown. `--speed max` or a number changes it.
- The command line now **reads data and DVD-Video burns back by default**, as the app already did (`--no-verify` skips it), and audio rips use error pointers and re-reads by default (`--no-secure` skips them).
- An audio burn **stops on a damaged FLAC file** (bad frames, cut short, wrong MD5) instead of burning silence in its place; `--allow-damaged` overrides.
- Titles and artists from **MP3, M4A and WMA tags** now reach CD-Text.

### Fixed
- Damaged CD-ROM sectors in images and rips are repaired with the parity every sector carries, or reported as damaged; a sector of zeros is no longer taken as good data.
- DVD-Video authoring stretched pictures that were not already 16:9 (a 4:3 video played a third too wide); the picture now keeps its shape, with bars.
- Burns through the Windows writer reported the speed asked for; they now report the speed reached while writing.
- A DVD-R's table of contents can leave out sessions right after one is added; IgnisDisc now checks it against the drive's track list, so adding another session no longer risks reading an older one.

### Known limitations
- Direct drive commands are experimental and have been tried on one drive model only. DVD-RW, DVD-RAM, dual-layer DVDs and Blu-ray have run only against the built-in drive simulator; Blu-ray burning has never been tried on a real drive.
- No disc from this release has been played in a stand-alone CD or DVD player.
- After a session is added to a DVD-R, Windows may show only the earlier files until the disc is taken out and put back in.
- On a spring-tray drive, a test write followed by a real burn needs the disc reloaded by hand.
- Discs left open for more sessions hold file names of up to 64 characters.
- The lower default speed for weak CD-R batches applies in the app; the command line does not apply it yet.
- MP3 and Opus ripping need the optional ffmpeg download.
